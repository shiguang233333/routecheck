# 分流体检 · routecheck

一个纯前端的代理分流与延迟检测页。打开后扫描 36 个常用站点和 8 个 IP 出口查询服务，用来判断域名级分流是否按预期工作，并比较国内、国际线路的 HTTP 延迟。

## 运行

```bash
cd routecheck
python3 -m http.server 4173
```

然后打开 <http://127.0.0.1:4173>。也可以直接双击 `index.html`，但部分浏览器的跨域限制在 `file://` 下更严格，建议用本地服务器。

## 检测逻辑

- **出口指纹**：8 个 IP 查询服务，其中 `myip.ipip.net` 与 `whois.pconline.com.cn` 位于国内作为对照（pconline 通过 JSONP 读取）。国内、境外域名如果返回不同 IP，通常说明分流规则在生效。
- **目的地矩阵**：36 个站点分成国际、AI、流媒体、社交、国内五组，每个最多请求三次，取最快一次。可以逐个勾选，或使用全选 / 取消全选。
- **实时延迟**：对自定义 URL 每 2 秒发起一次请求，显示最近 40 次的最快、平均、最慢与丢包率。
- **判定**：基于出口 IP 是否一致、延迟差和可达性给出提示，不读取代理客户端配置。出口 IP 按 IPv4 / IPv6 分组比较，避免双栈地址被误判为分流。
- **示波屏**：每根柱子代表一个站点；鼠标悬停或点按可查看该站点的名称、延迟和推测线路。

## 限制

- 浏览器不能发 ICMP。延迟是 DNS、连接、TLS 加一次 HTTP 请求的总时间，不等同于 `ping` 的 RTT。
- 探测结果依赖目标服务的 CORS 策略与可用性；某个出口查询失败不代表性网络不可用。
- `「推测」` 标签只依据延迟和可达性，不代表代理客户端的真实规则。
- 所有请求由浏览器直接发出，页面不带后端，也不上传扫描结果。

## 部署

这是纯静态站点，可以直接由 GitHub Pages 从 `main` 分支根目录发布。仓库根目录已包含 `.nojekyll`，不需要构建步骤。

## 文件

- `index.html` — 页面结构
- `styles.css` — 视觉与响应式布局
- `app.js` — 探测、判定、仪表波形与实时监测
